## 1. 结论

当前数据对本项目的 **MVP 和后续 Agent 主链路已经够用**，不再继续批量读取全部资料。下一阶段可以进入数据库建模和入库。

这里的“够用”指：能够先跑通“自然语言问题 → 结构化财务事实查询 → Python 计算 → 后续年报 RAG → 图表/报告”的核心闭环；不代表已经覆盖泰迪杯 B 题的全部时间粒度、全部指标和全部研报。

## 2. 本轮读取策略

按照“同一类型最多抓前十个、摘要跳过”的约束，本轮只读取一大类资料：

- **资料类型**：非摘要年度报告；
- **数量**：10 份；
- **选择方式**：B 题目标公司每家公司 1 份 2024 年年度报告；
- **表内时间覆盖**：年度报告中的“近三年主要会计数据和财务指标”提供 FY 2022、FY 2023、FY 2024；
- **暂不读取**：年度报告摘要、全部历史财报、季度报告、全部研报；
- **原始资料目录**：`资料待放入/正式数据/附件2：财务报告`；
- **抽取程序**：`src/finance_insight/ingestion/extract_mvp_dataset.py`。

选择 2024 年年报而不是分别读取 2022—2024 年 30 份年报，是因为本项目当前优先验证数据建模和 Agent 工具链，而年报摘要表已经同时给出近三年核心指标。这样可以在不扩大读取量的情况下获得跨年度趋势分析能力。

### 3.3 指标

**8 个原始指标**：

- `revenue`：营业收入；
- `net_profit_attributable`：归属于上市公司股东的净利润；
- `net_profit_excl_non_recurring`：归属于上市公司股东的扣除非经常性损益的净利润；
- `operating_cash_flow`：经营活动产生的现金流量净额；
- `eps`：基本每股收益；
- `roe`：加权平均净资产收益率；
- `total_assets`：总资产；
- `net_assets`：归属于上市公司股东的净资产。

**2 个由 Python 计算的衍生指标**：

- `net_margin`：归母净利润 / 营业收入 × 100%；
- `operating_cash_margin`：经营活动产生的现金流量净额 / 营业收入 × 100%。

统一金额单位为“万元”，比率单位为“%”，每条记录同时保留原始值和标准化值。

## 6. 现在已经能支持的问题

当前数据可以支撑以下第一批 SQL、Python 和图表场景：

1. 查询某家公司 2022—2024 年营业收入、归母净利润、ROE；
2. 查询某家公司三年经营现金流及经营现金流率；
3. 计算收入、净利润、ROE 的年度趋势和同比变化；
4. 计算净利率、经营现金流率、利润增速等衍生指标；
5. 比较 2024 年 10 家公司的营业收入、净利润或 ROE；
6. 识别收入、利润、ROE 的异常波动年份；
7. 为趋势图和横向对比图提供完整数据；
8. 后续从这 10 份年报中检索经营情况、风险因素、业务变化等解释性原文。

## 7. 当前明确不支持的问题

以下能力需要后续扩展数据，当前不在 Phase 2 阻塞范围内：

- 2025Q3 等季度或半年度滚动比较；
- 资产负债表、利润表、现金流量表的全部科目；
- 全部 B 题问题集的所有指标和口径；
- 大规模研报观点对比、券商评级和目标价分析；
- 需要逐年全文对照的复杂原因归因；
- 投资建议、股价预测或收益承诺。

## 9. 进入 Phase 2 的判断

现在继续读取更多同类文件的边际收益较低，反而会把注意力从数据库设计和可验证工具链上分散。当前数据已经同时具备：

- 跨公司维度；
- 跨三年时间维度；
- 核心盈利、规模、现金流和效率指标；
- 原始值到标准化值的单位转换；
- 年报文件和页码溯源；
- 衍生指标计算样例；
- 可通过自动脚本重复生成和验证。

因此本阶段结论为：**数据范围冻结，进入 Phase 2：先用 SQLite 跑通关系模型和查询，再迁移 MySQL。**
