# FinanceInsight Agent 作品集评估

## 结论

**可以拿去面试展示。** 它适合 AI 应用开发、AI Agent、数据应用或金融科技方向的中初级工程岗位，也已经具备完整作品集的四个关键信号：真实问题、可运行界面、工程化后端、可复现验证。

它目前不应被包装成“生产级金融分析平台”。更准确、也更有说服力的定位是：

> 一个面向财报分析场景、以确定性数据与可追溯证据为核心的可运行 AI Agent 工程样机。

综合准备度：**8.2 / 10**。评分用于决定改进顺序，不代表招聘结论。

- 复合问题实际返回结构化事实、Python 计算、RAG 引用、图表和工具轨迹；
- Docker 中 `/health` 返回 MySQL、Redis 和合成 Demo 均正常；

## 面试时的主导航

### 1 分钟：给 HR 或非技术面试官

“财务分析师回答一个跨年度问题，通常要在数据库、年报和计算表之间来回核对。这个项目把问题先变成结构化意图，再让受控 SQL 取事实、Python 做同比和 CAGR、RAG 找带页码的原文依据，最后输出图表和完整工具轨迹。公开版本用合成数据，因此面试官可以直接克隆运行；没有 API Key 也能完成核心演示。”

### 5 分钟：给技术面试官

1. 打开工作台，展示合成数据提示和当前 MySQL/Redis 状态。
2. 提复杂问题，依次看 `Structured Intent`、结构化事实、计算结果、引用和 Trace。
3. 打开 `/health`，说明 requested/effective backend、fallback 和并发限制。
4. 打开 `/docs`，证明查询、异步任务、会话与评测都有正式 API。
5. 运行 `pytest` 和 `evaluate-demo.ps1`，把结论从“看起来能用”变成“可以验收”。

## 可以主动说出的技术决策

- **不让 LLM 直接写 SQL**：模型只产出白名单意图，SQL 模板使用绑定参数。
- **不让 LLM 直接算财务数字**：事实来自 SQL，同比/CAGR/异常由 Python 计算。
- **RAG 不是装饰**：公司/年份过滤、FTS 与向量双路召回、融合重排，并返回文件、页码和 chunk。
- **失败必须可见**：LLM、数据库、Redis 或向量索引异常时，响应中保留状态、原因和降级标志。
- **评测覆盖业务契约**：不只看接口 200，还检查意图、工具路径、数值、引用和图表。

## 应避免的夸大

- 不要说“真实上市公司财务结果”；公开数据全部是合成的。
- 不要说“生产级准确率或因果分析能力”；引用覆盖不等于因果关系成立。
- 不要说“所有可选组件都已端到端验证”；真实 LLM、远程 BGE-M3 仍需配置 Key 单独验收。
- 不要说“支持任意 NL2SQL 或完全自主多 Agent”；当前是受控指标、固定工作流和有限状态编排。
